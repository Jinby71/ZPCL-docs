# 项目结构

仓库包含一个 Gradle 应用模块，模块名沿用上游的 `ZalithLauncher`。界面、下载、启动与插件管理均在该模块内。

## 顶层目录

| 路径 | 内容 |
| --- | --- |
| `ZalithLauncher/` | 启动器主模块 |
| `…/ui/pcl2/` | PCL2 版式界面：外壳、左栏、各版块页面 |
| `…/ui/pcl2/components/` | PCL 控件库：按钮、列表项、卡片、弹窗、下拉 |
| `…/game/` | 下载、启动、渲染器、插件管理 |
| `docs/PLUGIN_GUIDE.md` | 插件协议原文 |
| `docs/THIRD_PARTY.md` | 第三方组件与许可清单 |
| `latest_version_md.json` | 应用内「检查更新」读取的版本清单 |

## 界面层

PCL2 版式的实现在 `…/ui/pcl2/`。外壳与左栏负责版块切换，五个版块（首页、下载、版本设置、联机、设置）各对应一个页面。控件统一由 `components/` 提供，新增界面时优先复用其中的控件，避免与既有版式产生差异。

## 业务层

`…/game/` 存放下载、启动、渲染器与插件的实现。资源获取、实例安装、启动参数组装与渲染器选择都在这一层，不直接依赖界面代码。

## 文档与元数据

`docs/PLUGIN_GUIDE.md` 是插件协议原文，本站[插件 API](/dev/plugin_api)据此整理；表述不一致时以原文为准。`docs/THIRD_PARTY.md` 记录第三方组件与其许可，站点整理为[第三方组件](/third-party)页。`latest_version_md.json` 由客户端读取，用于版本检查与更新提示。

## 阅读顺序

改动界面时，从 `ui/pcl2/` 的外壳与左栏入手，再定位到对应的版块页面。改动下载、启动或渲染器行为时，从 `game/` 进入。插件相关逻辑同样位于 `game/`，协议部分需对照 `docs/PLUGIN_GUIDE.md`。

## 不可修改的标识

`launcher_name` 与 `CLIENT_TOKEN_SEED` 决定登录与数据目录的位置。修改后既有用户的数据目录不再匹配，升级时表现为设置与实例丢失。
